# 🌀 Vision — Diversion

**Diversion is a personal gallery of small, screensaver-like generative-art pieces.** Each piece — a *diversion* — is unrelated in content (a particle flow field today, a cellular automaton or a raymarcher tomorrow), but they all share one framework and one design ethos. The framework owns the *chrome* — routing, the rAF loop, pause, fullscreen, the config form, and the URL codec — so a diversion is a black box that only has to draw. The reward is compounding: every new framework capability lifts every diversion at once, and a new piece is just a folder that gets auto-discovered.

The intended experience is two-sided. A **viewer** opens the animation screen full-bleed and lets it run as a living wallpaper; any look is a shareable URL, because the entire configuration is encoded in the link. A **tinkerer** opens the config screen, where every parameter is discoverable and adjustable beside a live preview — collapsible sections, subpanels and mode-dependent swaps are all fair game, so long as a control is easy to find and its value comes back when you open the section; help text where it would otherwise confuse. The five UX invariants (readability, discoverable-not-buried, inline-help, sliders-only-when-bounded, more-contrast) are the spine of that screen and are treated as MUST, not polish.

**What this deliberately is NOT:** not a general-purpose creative-coding library or framework for others to build on; not a node-graph or live-coding editor; not a social platform with accounts, feeds, or persistence beyond the URL. It is a single-author playground whose constraints — one schema per diversion as the single source of truth, GitHub Issues + Releases as the only tracker, deploy-on-push to GitHub Pages — exist to keep the surface small enough that building diversions stays fun rather than becoming infrastructure work.

The arc so far: started 2D on Canvas, proved the framework against a reference flow field, grew the diversion contract (pointer/input seams, a live-update hook, run persistence), and reached for **WebGL** and then **WebGPU** when a piece genuinely needed the pixels — all three kinds now carry pieces in the gallery. That ordering is the invariant, not the endpoint: breadth of *pieces* and depth of *framework* advance together, and neither runs ahead of the other.
