# Diversion — project conventions

A gallery of independent screensaver-like generative-art "diversions" sharing one framework + one design ethos. Read `README.md` for orientation, `docs/superpowers/specs/` for the design spec.

## Commands

```bash
npm run dev      # Vite dev server, pinned to port 5180
npm test         # vitest run (full suite; ~22s, 6871 tests in 328 files)
npx vitest run src/diversions/<slug>   # one diversion's co-located tests
npm run lint     # oxlint
npm run build    # tsc -b && vite build
npx tsc -b --noEmit                    # typecheck only
npm run size     # entry-chunk + precache budgets (needs a fresh `npm run build`)
npm run check:pwa                      # service worker + manifest contracts
npm run check:preload                  # deep-link modulepreload map (needs a fresh build)
npm run check:cache                    # every emitted file has exactly one caching lane (fresh build)
```

Dev URLs have **no** `/diversion` prefix (that's prod-only): `http://localhost:5180/d/<slug>/play`. A brand-new diversion folder 404s until the dev server is restarted — Vite's `import.meta.glob` registry doesn't pick it up live.

## Architecture (load-bearing)

- **The framework owns the chrome; a diversion is a black box that draws.** A diversion implements `{ id, title, description, kind, schema, setup, frame, resize?, update?, teardown? }` (`src/framework/types.ts`). The framework owns the `requestAnimationFrame` loop and calls `frame(state, ctx, t, dt)` each tick. Diversions never touch React. **Pointer input (#9)** rides the same black-box rule: a diversion opts in with an optional `onPointer?(state, sample)` hook, and `AnimationHost` owns the canvas listeners — it normalizes each event into the diversion's own draw space (CSS px for `2d`, device px for GPU kinds, plus 0..1 `nx/ny`) and tears them down on switch/unmount. The diversion never reaches the canvas or re-derives DPR. Listeners are wired only when the hook exists.
  - **The seam has exactly one consumer** (`falling-sand`) and three diversions that go *around* it: `particle-life-gpu`, `swarmalators` and `swarm-chemistry` attach their own `ctx.canvas` listeners in `setup()` for a drag-pan / wheel-zoom camera, because `onPointer(state, sample)` cannot express wheel, pointer capture, or a persistent view transform. That divergence is known and accepted; what it costs is that those listeners live outside React and **cannot see the `interactive` prop**. So `AnimationHost` publishes it as **`data-interactive`** on the canvas and `framework/canvasGestures.ts` reads it back (`drivenByViewer`). Use that, never a width heuristic (#290): each of the three used to infer it from `clientWidth >= 480`, which is TRUE of a gallery **tile** at viewports around 530-628px where the grid is one column — so a tile called itself interactive and its `{passive:false}` wheel handler blocked page scroll over it, on a plain mouse, with a green suite. A missing attribute reads as *not* interactive on purpose: an inert camera is visible and recoverable, an eaten scroll is neither.
  - **`interactive` alone is NOT enough for touch — you need both halves.** Such a diversion also declares **`ownsCanvasGestures: true`**, which buys it exactly one thing: the `.anim-canvas--interactive` class (`touch-action: none`), still gated on `interactive`. Without it the class is gated on `onPointer`, which these don't declare, so the canvas kept `touch-action: auto` and a finger drag panned the camera *and* scrolled the page. The flag must never wire framework listeners — `AnimationHost`'s listener effect still keys on `onPointer` only. And the flag isn't sufficient either: below 820px `.config-preview` deliberately hands `touch-action` back (that page scrolls, its preview is sticky), while the mount is still `interactive` — so the diversion gates touch on **`gesturesYielded(cv)`** (computed `touch-action === 'none'`). `drivenByViewer` answers "is this mount viewer-driven"; `gesturesYielded` answers "may a *finger* here mean something other than scrolling". They come apart on exactly that one surface. Gate the drag on `isPrimary`, `button === 0` (pointerdown fires for the right button, and `isPrimary` is true for a mouse whichever is down), and track the owning `pointerId` — a boolean `dragging` let a *second* finger's `pointerup` kill the first finger's drag.
  - **The WHEEL gets its own third predicate — `wheelOwned(cv, e)` (#294) — and NOT `gesturesYielded`.** `touch-action` is a touch property with no bearing on wheel; keying wheel policy on it would work only by coincidence of which rule the 820px media query happens to override, and it would leave the Config preview below 820px able to pan and double-click-reset with a mouse but never to zoom. So gate each device on the contest it actually has: `wheelOwned` consumes the wheel when the mount is viewer-driven **and** either nothing behind the canvas can scroll (`pageScrolls(cv)`, the scrolling element only — an ancestor walk would need a `getComputedStyle` per element per event) **or** the event carries `ctrlKey`. That last clause is not a hack — a trackpad **pinch is delivered as a wheel event with `ctrlKey` set**, so the escape hatch is the gesture a viewer reaches for anyway, and trackpad pinch-zoom falls out for free.
  - **⚠️ Every touch path in this seam is verified SYNTHETICALLY only (#297).** #290's and #295's gestures were driven by hand-built `PointerEvent`s and Chrome emulation; no real touchscreen has ever run this code. That is exactly the gap that let #290's original defects ship (`e.movementX` undefined for touch, a second finger's `pointerup` killing the first finger's drag) — a synthetic pointer has whatever properties the test gives it. Treat a green camera suite as evidence about the logic, not about the device.
  - **Touch pinch (#295) shares only its DECODING.** `createPinchTracker()` in `canvasGestures.ts` is pure two-pointer bookkeeping — the traps are a zero divisor on the frame a pair forms (`Infinity` survives a `Math.min/max` clamp exactly like the `movementX` `NaN` did), a third finger with no stable pair to measure, and the 2→1 handover, which must re-seed the drag's `last` from where the surviving finger **is** or the next move applies the whole pinch travel in one step. What stays in each diversion is `zoomAbout(devX, devY, factor)` — the wheel and the pinch are the same two callers of it — because the three cameras' fit basis, pan clamp and even y-sign mirror their own WGSL. Hoisting the transform would invert the black-box rule; hoisting the decoding does not.
  - **A camera that owns its own listeners must not read `e.movementX`.** It is absent for touch pointers on some engines, and `panX -= undefined * n` is `NaN` — which a `Math.min/max` clamp *propagates* rather than corrects, so a single touch drag destroys the view until reload. Track the previous `clientX/Y` yourself. Gate on `e.isPrimary` too, or a second finger starts a rival drag, and guard `releasePointerCapture` (it throws `NotFoundError` on the `pointercancel` path). `camera.test.ts` in each of the three covers all of it — that code shipped with **zero** tests, which is exactly how these defects survived a Chrome verify.
- **One Zod schema per diversion is the single source of truth** — it drives the config form, the URL codec, AND the `Config` type. Each field carries `.meta({ ui, label, help, min, max, step, options })`.
- **`kind: '2d' | 'webgl' | 'webgpu'`** selects which context the host acquires. 2D contexts are DPR-scaled so sims draw in CSS pixels; the GPU kinds (`webgl`/`webgpu`) get device pixels.
- **Registry auto-discovers** diversions via `import.meta.glob` — a new folder is picked up with no registration. Since **#288 it is TWO globs over the same folders**: `*/meta.ts` **eager** (identity — `{id,title,description,kind}`, four strings, no imports) and `*/index.ts` **lazy** (the implementation, one emitted chunk each, fetched on demand). So a diversion folder needs **both files**, and `index.ts` spreads `...meta` rather than restating the fields — single source of truth, with `contract.test.ts` asserting the two agree and that the two globs' slug sets match. A folder with `index.ts` but no `meta.ts` silently vanishes from the gallery and 404s its route: no type error, nothing thrown. That test is the only thing that catches it.
  - **`schema` is deliberately NOT in the metadata.** It looks like it belongs (the gallery used to call `schema.parse({})` per tile), but eager-globbing the 137 schemas drags all of zod into the entry chunk for **+142 kB gzipped**, more than doubling it — for a value nothing needs until a tile mounts, by which point its module has loaded anyway. The default-config parse moved inside `LazyPreview`'s loaded branch.
  - **Routes suspend; they do not load in an effect.** `useDiversion(slug)` returns synchronously when warm and otherwise `use()`s a memoized promise, so a route's first *executed* render already has a non-null diversion. That is what keeps `PlayScreen`'s `resumeConfig`/`armPersistence` seams and `ConfigScreen`'s once-only `useState` initializer byte-identical — an effect-based load would render once with `null`, making `if (!diversion)` ambiguous between "404" and "still loading" and re-ordering the persistence seam. `App.tsx` wraps both `/d/:slug` routes in `<Suspense>` + `DiversionErrorBoundary`, keyed by slug.
  - **The promise cache KEEPS rejected entries, and that is deliberate.** (This line said the exact opposite until 2026-08-17; `3080d2f` inverted the behaviour after measuring it, and the doc never followed. Believe `registry.ts`, which carries the numbers.) Memoizing is required for `use()` — a fresh promise each render suspends forever. Dropping the entry on rejection *looks* like it enables a retry, but React indexes tracked thenables positionally and discards any new promise handed to it on a replay, so an evicting cache produces a fresh `import()` per replay that React throws away: measured at 5 wasted imports before the boundary catches, and inside `act()` it never terminates (57k warnings in 30 s). Keeping the rejection surfaces the error in one pass. The consequence — a failed chunk is terminal for that id until a reload — is not a compromise: the browser's module map caches the FAILURE against the URL (three `import()`s of a 404ing specifier produce exactly ONE network request), so even perfect eviction plus remount replays the same rejection with no fetch. `RouteLoadError` (#292) is the affordance, and it reloads. Relevant in the real world: a deploy replaces the hashed chunk filename under an open tab.
  - **Fetch on the DEBOUNCED `near` state, never the IntersectionObserver callback.** The callback fires per tile per crossing, so a fling down the 50,000px gallery would start 137 imports; on `near`, the existing 160 ms mount debounce filters them (measured: a hard fling issues zero). `kind` lives in the metadata precisely so the GPU-slot budget stays decidable *before* any module loads.
  - **`framework/testRegistry.ts` is the test-only eager registry.** Vitest does not bundle, and the sweeps iterate at module scope to generate one `it()` per diversion, so they keep eager-globbing all 137 real diversions — the keystone codec/seed/urlKey guarantees are unchanged. A production import of it silently restores the 1.9 MB entry with every test still green; `contract.test.ts` greps for that, and `npm run size` catches it independently in CI.
  - A route test that renders `PlayScreen`/`ConfigScreen` without a Suspense boundary must `await loadDiversion(slug)` in `beforeAll`, or it suspends forever and fails with "Unable to find an accessible element" against an empty body — which reads like a markup bug and is not one.
- **Config ⇆ URL codec** (`framework/urlCodec.ts`): **full snapshot** — every field is encoded (no omit-defaults), under **flat leaf-name keys** (`colors`, not `color.colors`; a leaf name that isn't globally unique in the schema falls back to its dotted path — guarded by `urlKeys.test.ts`). Decode degrades **per-field** (an invalid field reverts to its own default; the rest survive) and legacy dotted-key URLs still decode. A link is therefore a permanent snapshot, immune to later default changes (#4). **Exception — `randomizeOnFreshLoad` fields (a `seed`) are pin-only:** `encodeConfig` never emits them, and the route layer (`applyFreshLoadRandomization`, called in Play/Config screens) rolls each one fresh whenever the URL omits it — so a shared link is seedless and shows a new world every visit, while an explicit `?seed=N` (for testing / exact reproduction) is honored. It is the keystone — keep it fully tested. **Second exception — `local: true` fields never travel at all (#278):** a field holding an id for something that lives only in THIS browser (an uploaded image, whose pixels sit in `framework/imageStore.ts`) is skipped by `encodeConfig` in **both** modes, unlike a pin-only seed which IS emitted under `includePinned`. Don't conflate the two flags — `randomizeOnFreshLoad` also drives `applyFreshLoadRandomization`, which would try to roll a random *string*. `codecSweep` needs no change for a `local` field that is `.optional()` with no default: it's already excluded for carrying no value at defaults, exactly like a Custom-only matrix override.
- **Presets are declared data, not chrome** (`framework/presets.ts` + `PresetGroup`/`PresetOption` in `types.ts`). A diversion optionally declares `presets?: PresetGroup<Config>[]` — named groups (independent axes, e.g. Flow Field's `Flow` + `Color`) whose options each carry a `patch: Partial<Config>`. `ConfigScreen` renders one `<PresetPicker>` dropdown per group above the form; picking applies `{...config, ...patch}` through the same `update` path the form uses (so canvas + controls + URL stay in lockstep), and `matchPresets` flips a group to "Custom" the moment a manual edit drifts off the preset. Top-level spread, so a nested group (`color`) must be patched whole. Honors the black-box rule — the framework renders; the diversion only describes. `matchPresets` assumes equal key-sets per group (see its comment).

## The five UX invariants (treat as MUST)

1. Readability is key. 2. **Discoverable, not buried** — every variable stays **discoverable**, and carries a hint/help when its effect isn't obvious. Values do **not** have to be on-screen 100% of the time: collapsible sections, subpanels, and mode-dependent swaps (a `showWhen` panel showing only the active mode's options — e.g. the Color panel's palette-vs-gradient controls) are all fine, as long as the control is easy to find and its value returns when you open the section / switch the controlling field. Discoverable ≠ always-on-screen. 3. Add inline help when confusing (`.meta({ help })`, persistent — not hover-only). 4. Sliders only when bounds are defined (`ui:'slider'` needs min/max; open-ended → `ui:'number'`). 5. Err toward more contrast.

## Conventions

- **Tests:** Vitest, co-located `*.test.ts(x)` next to sources. Pure logic (codec, noise, loop) is unit-tested; UI via @testing-library/react. Anti-regression must-haves: codec round-trip + resilience, control-selection-from-schema, noise determinism.
- **Stack:** Vite + React 19 + TypeScript + Zod 4. Custom `SchemaForm` (no form-generator dep) and custom URL codec. React Router for the 3 routes.
- **Dev server:** pinned to **port 5180** (`vite.config.ts`).
- **Verify in Chrome** (chrome-devtools MCP), never a built-in preview. Visual quality matters — verify the animation actually looks good, not just that it renders.
- **Git identity:** `MattAltermatt <1435066+MattAltermatt@users.noreply.github.com>`. Branch `feature/...`, FF-merge to `main` after verify.

### Schema UX canon (#256) — the gallery reads as one system

A new diversion copies this canon; it's what the majority of the 137 already do. All of it lives in `.meta({...})` — none of it touches the URL codec (the codec keys on field name + value, never `section`/`label`/`collapsed`), so aligning an existing schema to canon is codec-safe and default-preserving.

- **Palette:** a piece that *cycles many colors* uses a single `ui:'colorList'` field named **`'Palette'`**. Discrete `ui:'color'` fields (in a `ui:'group'`) are only for colors that are **distinct semantic roles** (species A/B/C, core/halo/ember, sky/terrain).
- **Background:** the ground color is a `ui:'color'` field named **`background`**, label **`'Background'`**, with a **dark default** (err toward contrast, invariant #5). A full-field simulation whose palette paints every pixel may legitimately omit it (the palette's dark end *is* the ground) — that's the only sanctioned exception; don't editorialize the label ("Grout", "Plate") — say `'Background'`.
- **Sections:** color controls live under section **`'Color'`** (not `Colour`/`Style`/`Look`). The power-user tail (seed + rarely-touched knobs) lives under section **`'Advanced'`**, which **starts collapsed** — set `collapsed: true` on the seed field (SchemaForm collapses a section if *any* field in it declares `collapsed`). Discoverable, not buried (invariant #2).
- **Seed:** a seeded piece has a field named **`seed`**, label **`'Seed'`**, `ui:'number'`, `randomizeOnFreshLoad: true`, in section **`'Advanced'`** with `collapsed: true`. (Guarded by `seedContract.test.ts`.) A genuinely deterministic piece has no seed.
- **Presets:** the color/appearance preset axis is a `PresetGroup` labeled **`'Palette'`** (independent axes for orthogonal choices, `Custom` fallback on manual drift — `matchPresets`).
- **Help:** every non-obvious field carries persistent `.meta({ help })`.

Known **not-yet-canon** debt (tracked in **#259**, not a blocker): a couple of dozen pieces invented per-diversion color *mode* enums (Glow/Solid/XOR, spectrum/palette `showWhen` swaps, dual-`colorList`) — unify later; **53 of 137** pieces have no `'Palette'` preset group (84 declare one) — add later. Recount before quoting these; the previous figures here (69/67) did not survive a recount. Count with `grep -rlz "label: 'Palette',[[:space:]]*options:"` per diversion folder — matching `label: 'Palette'` alone over-counts, because the canon `colorList` **field** carries that same label.

### Small screens (#284) — the first `@media` queries in the project

Everything above the breakpoints is the layout that shipped for a year; the
mobile rules only apply below, so desktop is unchanged by construction. Two
thresholds, both derived: **820px** (320px sidebar + ~500px usable preview is
where the Config split stops working — below it the screen stacks, preview
sticky on top at `clamp(240px, 45vh, 420px)`, panel flowing beneath) and
**560px** (the Play chrome and the anim bar are anchored to opposite edges and
collide below ~524px — below it the chrome moves bottom-left and its labels
collapse to glyphs). **Touch targets key off `@media (pointer: coarse)`, not
width** — a phone in landscape is 932px and a finger is no more precise there.

- **`touch-action: none` is gated on `interactive && diversion.onPointer`**, never
  on `.anim-canvas` alone. The same canvas class is used by all three routes, and
  `touch-action` is honoured by the compositor whether or not a JS listener
  exists — so the blanket version silently makes the 50,000px gallery
  unscrollable. `pan-y` is not the answer either; a paint-style hook drags in both
  axes. `AnimationHost`'s `interactive` prop (false for Gallery tiles) gates the
  class *and* the listeners; `.config-preview` additionally takes the gesture back
  below 820px, because that page scrolls and its preview is sticky.
- **Touch targets: grow the LAYOUT box, not an absolute overlay (#290).** The `.sw`
  switch reaches 44x44 under `@media (pointer: coarse)` by moving its painted pill to
  `::before` (`::after` was already the knob) — an overlay reaching ±12px would give
  stacked toggles *overlapping* hit areas, since two help-less booleans in a `.group`
  sit only 15px apart, and a mis-tap flipping the wrong field is worse than a small
  target. Two traps: `*` does not match pseudo-elements, so `::before` must state its
  own `box-sizing` or the 1px border makes the pill 2px too tall; and base `.sw.on`
  (0,2,0) outranks a bare `.sw` (0,1,0) **even from inside a media query**, so the
  on-state rules must be restated there or the accent paints the whole 44px box.
  Note this is a *usability* fix, not a conformance one — 38x20 already passes
  WCAG 2.2 SC 2.5.8 (AA) via its **Spacing exception** at this app's 35px worst-case
  pitch. The conformance bug in that control was the missing accessible name (4.1.2,
  Level A): the label is a sibling `<span>`, not a `<label for>`.
- **Safe-area padding does not belong inside a width query.** `viewport-fit=cover`
  is set, so `env(safe-area-inset-*)` is live — and a Pro-Max phone in *landscape*
  is 932px, keeping the desktop layout while carrying a ~59px inset. Overlay
  offsets (`.anim-bar`, `.play-chrome`, `.animate-pill`, `.reset-pill`) and panel
  padding (`.config-panel`, `.gallery`) are authored on their **base** rules;
  `env()` is 0px on every other device.
- **`100dvh`, not `100vh`** (`.config-screen`) — `100vh` is the URL-bar-retracted
  height on mobile Safari, so with `overflow: hidden` the bottom of the form was
  unreachable. Keep the `vh` line above it as the fallback.
- **Wake Lock lives in `PlayScreen`, never `AnimationHost`** (the host mounts on
  all 137 gallery tiles, so a per-host lock holds the screen awake while merely
  browsing). It keys off `shouldPause()`, which also gives re-request-after-hide
  for free, since `hidden` is already a pause source.
- **The manifest omits `id` on purpose.** `id` resolves against `start_url`'s
  *origin*, and `mattaltermatt.github.io` is shared across every Project Page, so
  a relative `id` would collide with any sibling repo's PWA.
- **`import x from './theme.css?raw'` yields the EMPTY STRING under vitest** (CSS
  processing is off), so a test that greps the stylesheet passes vacuously. Read
  it with `node:fs` and assert the read was non-empty. Same trap for `index.html`
  if you forget to strip comments — a comment quoting the thing you're asserting
  will satisfy a file-wide match.

### Opt-in whole-gallery offline (#293)

`OfflineToggle` in the gallery header; the engine (`framework/offlineWarm.ts`) is **dynamically imported on first press**, with the mount-time half (the localStorage record, `currentFingerprint`) split into `framework/offlineState.ts`. That split is mechanical, not stylistic: one static import of the engine from the same file **defeats the dynamic one entirely** (`INEFFECTIVE_DYNAMIC_IMPORT`), and that is exactly what shipped once — the whole engine inlined into the entry chunk while four comments claimed it was lazy. `check-bundle-size.mjs` now greps the built entry for a string only the engine contains. Warming is just `fetch()` of each URL — the service worker's existing `CacheFirst` / `StaleWhileRevalidate` routes store the responses, so there is no new caching machinery. Live-validated: 165 targets (137 chunks + the 1.17 MB weights + `credits.json` + 26 sprites), then a piece never opened runs with the network genuinely dead.

- **The URL list comes from #291's map, republished on `window.__diversionAssets`.** Nothing else in the app knows every emitted content-hashed filename: `import.meta.glob` yields *loaders*, not URLs, and `?url` on a JS module makes Vite emit a **second copy** of the file as an asset. The publish must happen **before** the script's early returns — the gallery takes the first one, and the gallery is where the control lives. `PreloadMap.extras` exists for the same reason: neural-ca's weights are fetched by `?url` at run time and never precached, so the build map is the only place their hashed name is known.
- **Shared deps are excluded from the warm list** — they are precached already, so warming them re-downloads ~170 kB for nothing. Sprites come from `public/pictures/credits.json` (an array of `{slug,…}`, image at `${slug}.png` — the same derivation `pictureStore.pictureUrl` uses) fetched at run time, because `public/` is copied verbatim and never appears in the bundle.
- **A failed fetch is COUNTED, not thrown** — one chunk that moved mid-deploy must not abandon the other 137 — and concurrency is capped at 6.
- **The green tick is EARNED, twice over.** The whole feature rests on the assumption that the service worker stored what we fetched, and that is false with no SW controlling the document (dev, pre-`clientsClaim`, post-eviction) — so `verifyCached` samples `caches.match` before the claim is printed. And `collectTargets` reports `chunkCount`: with an old cached `index.html` the asset map is absent, only the sprites are enumerated, and warming 27 files with zero failures would otherwise print “the whole gallery works offline” over an offline copy containing not one piece. A partial result says “⚠ Mostly saved”, never “✓”.
- **Deploys are handled by asking, not by re-downloading.** Content hashes all move on a deploy, so a warmed copy goes stale and LRU evicts it. A fingerprint of the asset set is stored; a mismatch turns the control back into an offer ("Update offline copy") rather than silently repeating ~1.6 MB on someone's cellular data.

### Deep-link preload (#291) — the one piece of bespoke build code

`vite.config.ts`'s `preloadDeepLink` plugin emits a `slug -> [chunk, ...shared deps]` map plus ~350 B of code into `index.html` (one tag, **8.1 kB raw / 3.0 kB gz** for 137 diversions — index.html goes 1.3 → 4.2 kB gz, paid on every visit and free only because it stays inside the ~14 kB first congestion window), turning the URL's slug into `<link rel=modulepreload>` tags. The pure half is `src/framework/preloadMap.ts` (unit-tested against a hand-built bundle, including the emitted script itself, run through `new Function`); the plugin is a shell too thin to hold a bug. `npm run check:preload` re-checks the built `dist/` in CI.

- **The map must carry DEPS, not just the diversion chunk.** `__vitePreload` already asks for a dynamic import's static deps at import time, so the third hop is ONE round trip carrying chunk + deps together; removing one file from that batch leaves the batch. Subtract the entry's own static closure (Vite preloads that already) or every deep link fetches `metas`/`runtime` twice.
- **⚠️ WHERE the tag goes is the whole thing.** An inline `<script>` does not execute while a stylesheet declared *before* it is still loading. Injected at the end of `<head>` — after Vite's `<link rel=stylesheet>` — the links were created exactly when `__vitePreload` would have asked anyway: measured on Slow 4G as a **0 ms saving with the map still shipped**. But not *first* in `<head>` either: the tag is ~8 kB and `<meta charset>` must be serialized inside the spec's first 1024 bytes, so it goes immediately **after** the charset meta — ahead of every stylesheet and script, inside the window. `check-preload.mjs` asserts both halves, because nothing else can see either.
- **`fetchPriority = 'low'`, and `crossorigin` to match Vite's.** Without the priority, these links took slots ahead of the shell's own deps on an HTTP/1.1 server (6 connections) and pushed first paint out by ~500 ms — "fetch early, never ahead of the shell". Without `crossorigin`, the credentials mode differs from the eventual `import()` and the browser fetches every file **twice**.
- **Validate on the DEPLOYED site, not `vite preview`** — preview is HTTP/1.1, Pages is HTTP/2, and the connection-limit artefacts above are preview-only.
- **Strip the base before matching the slug.** A free-floating `/d/` match reads the base's own segments (under a base of `/d/`, `/d/d/ablation/play` yields the slug `d`).

### Service worker (#289) — two cache tiers, and an escape hatch with a sharp edge

`vite-plugin-pwa` (`generateSW`). The config in `vite.config.ts` carries the reasoning; this is the part that bites.

- **The precache is the SHELL ONLY** — 18 files / ~173 kB gz (17 / ~166 kB before #293 gave the offline-warm engine its own chunk, which `assets/*.js` correctly claims: it is shell code). The 137 diversion chunks, the 858 kB neural-ca weights and the sprites are **runtime-cached**. Precaching all of it would cost every first visit 1.7 MB and re-centralise exactly what #288 decentralised. The consequence, which is deliberate: **offline, a piece you have never opened will not run by default** (the gallery still shows all 137 cards — the metadata is eager). Browsing the whole gallery offline is an explicit opt-in rather than ~1.6 MB spent silently on everyone — see the #293 section above.
- **`chunkFileNames` routes diversion chunks to `assets/d/`.** That directory *is* the tier boundary: `assets/*.js` doesn't cross a slash, so one glob precaches the shell and one route runtime-caches the rest, with no negative lookahead. If that callback breaks, all 137 chunks land in `assets/` and get swept into the precache — a 10× first-visit regression with a green build. `npm run size` fails on it; don't remove that check.
- **`registerType: 'autoUpdate'`, not the `prompt` default — but know exactly what that buys.** It makes the new SW skip waiting, activate, and run `cleanupOutdatedCaches`; measured across three simulated deploys the precache holds at its entry count (17 at the time; 18 since #293) and storage goes *down* on cleanup. Under `prompt` + `skipWaiting: false` the new SW sits in `waiting` while any tab is open, so nothing is ever pruned and each deploy adds a whole generation. **It does NOT reload the page** — nothing imports `virtual:pwa-register`, so `injectRegister` emits the *simple* script (a bare `register()`, no `workbox-window`, no `activated` listener), and an open tab keeps running the old bundle until something reloads it naturally. That is deliberate: auto-reloading would restart a propped-up display mid-piece on every deploy. Wiring the reload is one line if the trade ever flips.
- **Shell-only precache does not make stranding impossible, only rare.** `cleanupOutdatedCaches` filters on `-precache-`, so the runtime caches survive an activation and a cached diversion chunk is still served. But diversion chunks statically import **precached shared chunks** (`metas`, `schemas`, `rng`, …), and those *are* evicted — so a stale document can still fail a lazy `import()` whose dependency is gone from the precache and 404 on Pages, which #292 makes terminal for that id until a reload. Narrow, and identical with no service worker at all; don't claim it can't happen.
- **Match the caching strategy to the URL's MUTABILITY, not the file type.** `assets/**` is content-hashed ⇒ `CacheFirst` is unconditionally correct (changed content ⇒ changed URL ⇒ a miss, never a stale hit). `public/pictures/*` is copied **verbatim with no hash**, so `CacheFirst` there would pin a stale sprite or a stale `credits.json` for the whole expiry window — it gets `StaleWhileRevalidate`. A future third asset lane needs this decision made explicitly.
- **`npm run check:cache` (#296) is what forces that decision to be made.** It gives every file in `dist/**` an **owning** lane — {precache manifest, a runtime `urlPattern`, a declared `UNCACHED` list} — and fails on anything owned by nothing. Today the partition is right *by coincidence* — `models-*.json` is the only non-JS/CSS asset under `assets/`, and neural-ca is the only `?url` import in the repo — so a second one (`.wasm`, `.woff2`, a bundled `.png`) would be cached by nothing, and `npm test`, `size`, `check:pwa` and `check:preload` would all stay green. The deliberate omissions — `sw.js`, `workbox-*.js` and the three launcher icons, which is the five the check prints, plus a `404.html` rule that matches nothing because `deploy.yml` creates that file *after* this step — are *declared with reasons* rather than skipped, so a new unclaimed file fails until someone writes down why. An exemption rule matching nothing is itself an error, except the one that declares `mayBeAbsent`.
  - **The issue's own three-way framing was wrong, and the fix does two things instead.** `PreloadMap.extras` is not a caching lane — it is part of the **warm** list, i.e. which URLs #293 fetches so the existing routes get a chance to store them. `assets/models-*.json` is legitimately in both, and a naive three-way partition would call it doubly covered forever. So the partition is over the two lanes that *store*, and warm coverage is checked separately, **in both directions**: every runtime-cached file must be warmed (nothing else will ever cache it, so "the whole gallery works offline" is false for it otherwise), and every warm URL must be a runtime-cached emitted file (or the bytes are fetched and discarded, or 404). Precached files are deliberately *not* warmed, which is why the first direction is stated over the runtime set and not over everything.
  - **The lanes are read from `dist/sw.js`, not `vite.config.ts` — and the shipped predicate is EVALUATED, not parsed.** Provenance is why it reads the emitted worker (a route the plugin dropped or reordered still looks right in the config); fidelity is why it `new Function`s the route's whole first argument and calls it, exactly as `check-preload.mjs` already runs the shipped preload script. The first version extracted the first regex literal followed by `.test(` instead, and an adversary pass killed it: narrow the route to `… && !url.pathname.includes('boxcar2d')` and the largest chunk is cached by nothing while the check prints 137 claimed and **exits 0** — the precise bug class it claims to exist for, passing green. It also rejected two of workbox's three documented capture forms (a bare RegExp, a bare string) as unreadable. Evaluating handles all three and every conjunct.
  - **Ownership is FIRST MATCH, because that is what workbox does** (`Router.findMatchingRoute` returns on the first hit; `precacheAndRoute` registers ahead of every `registerRoute`). So a file matched twice is stored **once**. Treating a second match as a failure — "two lanes storing the same bytes doubles the space" — rejected a legitimate config for a reason that does not happen; overlap is now reported as *shadowing*, and what fails is a file with no owner, plus a lane that ends up owning **zero** files (which now also catches a route fully shadowed by an earlier one).
  - **`maxEntries` is checked against each lane's population, with 25% headroom.** It is a correctness bound, not a budget: `ExpirationPlugin` deletes past it *as entries are written*, so a lane over its cap silently loses the overflow and the offline control still prints its green tick. Nothing else in the repo compares the two. Not hypothetical — the pictures lane is 27 against 40 and **#287 is an open issue to grow the sprite roster**.
  - The pure half is `scripts/cacheLanes.mjs` (`.mjs`, not `.ts` — CI is Node 20 and cannot import TypeScript), unit-tested in `scripts/cacheLanes.test.mjs`; reverting to literal-extraction fails 4 of those tests, and the naive character-class parser fails 5 more. Non-vacuity is explicit: fewer than 3 routes, fewer than 10 precache entries, an uncompilable capture, a lane owning zero files, **or an `UNCACHED` rule matching nothing** (except the one declaring `mayBeAbsent`) each fail loudly. The staleness guard watches `public/` and `vite.config.ts` as well as `src/` — the lanes are *defined* in vite.config.ts, so an src-only guard would happily report a lane that had just been deleted.
  - **`scripts/cacheLanes.mjs` re-derives `offlineWarm.collectTargets`** (same reason: it can't import the TS). A fourth source of warm URLs has to land in both places, or the check goes quietly incomplete rather than red. Both sides carry the warning. The re-derivation was already wrong once: `collectTargets` warms `credits.json` from inside `if (res.ok)` — whenever the manifest **parses**, empty or not — and gating it on "we found sprites" made the check blame the wrong file.
  - **What it does NOT establish:** anything cross-origin, an asset inlined under `assetsInlineLimit` (4 kB, so there is no file to own), or anything created after the build. And if a catch-all same-origin route is ever added, every file becomes shadowed — the fix then is to rank by registration order, not to weaken the check.
- **`maxAgeSeconds` is garbage collection, not correctness**, and is set *long* (180d) on purpose: `ExpirationPlugin` expires on access, so a short age would break the exact case the SW exists for — a shelf device offline for weeks finding its chunks expired and falling through to a dead network. `maxEntries` is the real bound.
- **`manifest: false` is load-bearing.** Passing a `manifest: {...}` object makes the plugin overwrite `dist/manifest.webmanifest` with Vue-green `theme_color`, a **white** `background_color` (a white splash flash on every standalone launch of a `#08080a` app) and an **absolute** `scope` that `manifest.test.ts` forbids — plus a second `<link rel="manifest">`. None of it fails a test, because `manifest.test.ts` reads `public/`, not `dist/`. `npm run check:pwa` diffs the two.
- **⚠️ `selfDestroying: true` is the emergency handle, and it deletes EVERY cache on the origin.** The generated destroyer does `caches.keys()` → `caches.delete(...)` unfiltered, and Cache Storage is keyed by **origin**, not by scope. `mattaltermatt.github.io` is shared with every other Project Page on this account, so pulling it would wipe a sibling PWA's caches too. Today no sibling has one (checked), but if that changes, filter to cache names containing `/diversion/` before shipping it. The reverse also holds: workbox's own `deleteOutdatedCaches` matches on `cacheName.includes(scope)`, so a hypothetical **root-scoped** PWA at `mattaltermatt.github.io/` would match our precache name as a substring and delete it — our sub-path scope protects us from siblings, not from a User Page. It also only reaches clients that visit again — it is not instant, and a parked tab may never see it.
- `navigateFallback` emits bare `"index.html"` and **that is correct** — precache entries resolve against the SW's own URL (`/diversion/sw.js`). Making it absolute breaks `vite preview` and dev. Guarded by `check-pwa.mjs`.
- **`deploy.yml`'s `cp dist/index.html dist/404.html` stays.** A controlled client never reaches it, but it still serves every first-ever deep link, every uncontrolled client, and every browser without SW support.
- **No SW in dev** (`devOptions.enabled: false`), so the port-5180 workflow never has a stale-cache debugging trap.

## Gotchas learned

- **`ctx.globalAlpha` is sticky state, and a per-item draw loop leaks it.** In a loop drawing N items where some draws set `globalAlpha` and others rely on alpha baked into a gradient/rgba fill, the un-setting draws inherit the **previous item's** value — only item 0 is right. Worse with a swap-removed pool: the pairing reshuffles when any item dies, so brightness *flickers*. Set `globalAlpha` explicitly on every path, including `= 1` before a fill whose stops already carry alpha (cost: chime's wake, shipped broken, survived a Chrome verify). Catch it by wrapping `make2DContext()` in a recording proxy and logging `globalAlpha` at each `fill`/`stroke` — invisible to static review.
- **An entity pool's size is a FRAME BUDGET, not a correctness bound.** Sizing from "how many could coexist" (`n * 3`) leaves unbounded cost when each entity has a big draw constant — chime hit ~1200 ripples and ~250ms frames at max wells, *permanently*, since the field saturated in seconds and never drained (so a quick verify never sees it). Measure peak concurrency across every shipped preset, then cap with ~3× headroom. Count overflow drops on state so a test can assert shipped regimes never reach the cap, and order side effects so a dropped item degrades to nothing visible rather than a phantom (flare *after* the pool check, not before).
- **A flow-field-style sim needs particle respawn/lifecycle** or all particles collapse onto one streamline. Missing-lifecycle = mechanism bug, not tuning.
- **A release/spawn gate that clamps its sub-frame remainder at zero quantizes every opening to a whole frame.** Decrementing an accumulator with `Math.max(0, acc - ds)` and then re-*assigning* the interval on release, instead of carrying the negative overshoot and *adding* the interval, rounds every gate opening up by up to one frame's travel — so "evenly spaced" output silently isn't, independent of anything downstream. Ablation's gate measured 126.7px openings against a 121.3px ideal (speed 400 / capacity 12) — a 51px gap beside a 142px one, 58% off even, before a single rotation had happened. Fix: `acc -= ds` (no floor) and `acc += interval` on release; clamp to zero only in the idle case, when the gate is blocked and unused credit must not bank into a burst.
- **An async asset behind a sync `setup()` needs a version counter, not a promise (#278).** `setup`/`resize` are synchronous, so a `localStorage`-backed image can't be awaited there. `framework/imageStore.ts` exposes a monotonic `storeVersion()`; the diversion stashes it in state and compares it each `step()`. Rebuild **immediately** on a change rather than at the next natural boundary — Ablation's lap is ~25 min at the slowest Track speed, so "wait for this picture to finish" means "wrong picture for the whole session". Every storage path is fail-soft (corrupt JSON, stale schema version, quota rejection, and `localStorage` access itself throwing in Safari private mode all degrade to "no image", never to a throw inside a render).
- **HiDPI:** size the canvas backing store to `cssW*dpr` and `setTransform(dpr,…)` for 2D so the sim works in CSS pixels (density + crispness). Reapply the transform on every resize (resizing a canvas resets its context state).
- **Config changes go through `diversion.update?(state, config, size)`** first (live-apply, e.g. swap `state.cfg` + recompute derived data); return falsy and the framework falls back to a full teardown + `setup`. `AnimationHost` runs `setup` in a `[diversion]` effect (live run held in a ref) and `update` in a `[config]` effect — so visual params don't reallocate. Structural changes a diversion can't apply live (flow-field: particle count, seed) just return false. Diversions without `update` re-run `setup` on every config change (the old behavior).
- **A live-editable field that feeds an entity COUNT should reconcile the population in place, not rebuild it** (`ablation`'s `resizeCrew` is the reference). **There is no debounce anywhere** between a slider and `update()` — `Slider` uses the native `input` event and `ConfigScreen.update` runs synchronously — so *every intermediate value of a drag* runs this code. Rebuilding the population there costs a full state rescan per pointermove (measured 1.15ms at `cellSize 2`, ~7% of a frame) **and** visibly resets the piece under the cursor. Three traps, all hit: (a) trim/grow must respect whatever per-entity invariant the sim has (Ablation must keep one turret per surviving colour, or the picture becomes unfinishable) — reuse the same allocator `setup` uses rather than trimming a tail; (b) an entity mid-flight must not be deleted where it stands if the piece promises it can't — mark it and let it leave at its natural boundary, which means the count sits above target for a beat and that is correct; (c) **guard the dormant phase** — if the allocation basis is empty (Ablation between pictures: no live cells, so the allocator returns all zeros), reconciling deletes the population and mints nothing. Early-out instead. A dormant phase can be long (a lap ≈ 25 min at the slowest speed), so a drag reaches it.
- **Zod 4:** `.meta({...})` chains after `.default(...)`; read it back with `.meta()`. Grouped fields are `.default().meta()`-wrapped — unwrap via `.unwrap()` to reach the `ZodObject.shape` (see `SchemaForm.asObject`).
- **A second asset lane needs its OWN store, not a second tenant in the first one (#278).** `framework/imageStore.ts` is one `localStorage` slot holding the viewer's upload; routing bundled assets through it would clobber that upload every time the asset changed. `framework/pictureStore.ts` is the sibling: in-memory only (a committed asset is static and the browser HTTP-caches it), keyed by stable slug rather than a random id — so it has no id-cannot-survive-reload problem and needs no `currentImage()` fallback. It asserts by test that it **never writes `localStorage`**, because that regression is invisible and destroys user data. Same version-counter pattern as `imageStore` for the async-asset-behind-a-sync-`setup()` problem.
- **A fail-soft test that checks "nothing happened" usually checks it too early.** Ablation's four `pictureStore` fail-soft tests all passed while a mutation that stored garbage on every error path survived: they asserted the slot was empty *before the promise chain had reached its `.catch`*. Fix is to make settlement observable — `ensurePicture` returns its settle promise purely so tests can `await` it — not to sprinkle ticks. **Always mutation-check a fail-soft test**; it is the class of test most likely to assert nothing.
- **A contrast constant calibrated against one background is a landmine (#278).** `quantize.ts` shipped `L_FLOOR = 0.40` to lift the darkest band clear of the ground — correct, but solved against `#05070a` *specifically*. Warming the default ground to `#2b2620` dropped that same band to 1.47 against a required 1.88, reintroducing the exact invisible-band failure the constant existed to prevent (and a *light* ground inverts it, killing the lightest band instead). `contrastFloor(background)` now solves it per-background by binary search over OKLab L at worst-case hue — a saturated violet carries the least relative luminance at a given L, so test the hue circle, not a neutral. It reproduces 0.390 for the old ground, which is how you know the derivation is right. **Anything keyed on the result must go in the memo key** — `quantKey` includes `background`, or a ground change is a stale cache hit.
- **Transparency = cells that start dead, and it is nearly free (#278).** `buildFieldFromIndices` takes a `coverage` mask and starts uncovered cells with `alive = 0`. Everything downstream already reasons in terms of `alive` (`buildFront` walks lanes for the outermost survivor, `crew` counts `bandAlive` over live cells, completion is `aliveCount === 0`), so a cell that was never alive behaves exactly like one a turret cleared — beams simply cross it. Exclude transparent pixels from the k-means too, or the void wins a cluster and becomes a band the turrets hunt. To make the picture a solid rectangle instead, matte the void as band 0 and shift image colours up one — but **keep a lightness gap between matte and artwork** (`MATTE_GAP`), or a sprite's dark outline dissolves into the card behind it and the silhouette stops reading.
- **Mining a sprite sheet beats hunting for compositions.** A paginated sweep of 1,473 CC0 OpenGameArt candidates turned up mostly tilesets and sprite sheets and few framed scenes — because OGA is a game-*asset* library. Slicing a sheet on its tile grid gives dozens of pictures from one licence check. Two traps: a sheet may have **no alpha channel** and sit on an opaque background (key it out by **flood fill from the border**, never a global colour replace, which punches holes through matching pixels inside the art) — assert alpha on the output so this fails loudly; and OGA search **paginates at 25**, so any "this category is thin" conclusion from an unpaginated sweep is worthless.
- **`ui:'image'` (#278):** the only control that owns state outside the config. It writes decoded pixels into `framework/imageStore.ts` (one slot, versioned, fail-soft) and puts an **id** in the field — the config never carries pixels, so it stays cheap to diff on a slider drag and safe to hand the codec. The field is `local: true` (see the codec bullet). The control subscribes to the store via `useSyncExternalStore` because a rehydrate resolves after the form has mounted.
- **Config-aware SchemaForm controls (`ui:'matrix'`, particle-life-gpu #204):** a normal control receives only its own field `value`; a control that needs sibling fields (the matrix grid reads `colors`/`palette`/`symmetry` and writes the whole config) gets a **dedicated `renderField` branch** passing `config={value}` + `onConfigChange={onChange}` (mirrors the `group` branch). Keep the control generic — it imports **no** diversion math; the diversion supplies derivation via a `meta.deriveFrom(config) => number[]` callback (`buildMatrix` stays in the diversion). A **variable-length optional field** (the matrix is `colors²`, `undefined` until Custom-edited) round-trips through the existing array codec, but: (a) length can't be validated in the codec (it can't see `colors`) — guard at the consumer (`resolveMatrix`); (b) clearing must **omit the key**, not set `undefined`, or `flatten` emits `matrix=undefined`; (c) the codec-sweep keystone test excludes optional leaves with no value in defaults (like pin-only fields). **Generator→derived-field reconciliation** (Seed/Species rebuild, Symmetry transform, Bias defer) rides a pure `Diversion.reconcile(prev,next)` hook applied in `ConfigScreen.update`.
- **WebGL diversions:** `setup`/`frame`/`resize?(state,size,ctx)` receive the context — only `teardown?(state)` does **not**. So (a) still set `gl.viewport(0,0,gl.drawingBufferWidth,gl.drawingBufferHeight)` per-frame inside `frame` (cheap, always tracks the live backing store) — `resize` is observer-driven (a `ResizeObserver` on the canvas, #7) and fires for container/fullscreen reflow too, but per-frame viewport stays the simplest correct approach; (b) stash the context in `state` so `teardown` can free GL resources (`disposeGL` the program/VAO) — the host's `[diversion]` effect runs `teardown` on diversion-switch but the `webgl2` context persists on the same canvas, so unfreed resources leak across gallery navigation. `plasma/index.ts` is the reference. The host creates `webgl2` with `{alpha:false, antialias:false, powerPreference:'high-performance'}` and handles `webglcontextlost`/`restored` (rebuild via `setup`); a context loss must `preventDefault()` or it never restores.
- **WebGPU diversions (`kind: 'webgpu'`):** `canvas.getContext('webgpu')` is synchronous (the host branches it like `webgl2`/`2d`), but the `GPUDevice` is async — so a webgpu diversion follows the **neural-ca ready-flag pattern**: `setup` returns sync with `ready:false`, acquires the device in a fire-and-forget tail (`framework/webgpu.ts` `getSharedDevice()` — ONE shared page-level device, never one per tile), configures the context + builds pipelines, then flips `ready`; `frame` no-ops until ready; `teardown` sets `disposed` so a late-resolving init frees instead of writing dead state. Hard-won gotchas (all cost a debugging detour on `particle-life-gpu`, the reference): (a) `teardown` frees buffers/textures but **never** `device.destroy()` — the device is the shared singleton. (b) Use **explicit** bind-group layouts, NOT `layout:'auto'`, whenever >1 pipeline shares one bind group — two compute entry points touching different binding subsets get *incompatible* auto-layouts and one bind group can't drive both (symptom: per-frame `[Queue].Submit([Invalid CommandBuffer])` validation spam). (c) A trail/accumulation effect needs its **own** persistent `RENDER_ATTACHMENT|COPY_SRC` texture — the swapchain rotates 2-3 textures, so `loadOp:'load'` on `getCurrentTexture()` is NOT reliably last frame; render into the owned texture and `copyTextureToTexture` to the swapchain (canvas `configure` usage then needs `COPY_DST`). (d) A two-pass sim (forces→integrate) needs NO ping-pong — each pass writes only invocation `i`'s own slot, and ending one compute pass before the next IS the sync boundary (mirrors the CPU two-pass). (e) TS 6.0's bundled `lib.dom` ships the WebGPU *interfaces* (`GPUDevice`, `GPUBuffer`…) but NOT the flag *value* namespaces (`GPUBufferUsage`/`GPUTextureUsage`/`GPUShaderStage`) — spell the spec-frozen bits out locally rather than add `@webgpu/types` (which duplicates the lib's interfaces). (f) `count`/perf ceilings for a compute sim are a **measured-in-Chrome** decision (all-pairs `particle-life-gpu` held 60fps to ~24-30K on an M-series GPU; `swarmalators` — global all-pairs, no radius cull, +cos/sin/2 divides per pair — held 120fps to 16K), not a guess. (g) A render **bind-group layout entry's `visibility` must include every stage that reads it** — when a fragment shader reads a uniform the vertex shader also uses (e.g. `swarmalators` reads `view.colorMap` to pick the phase→colour wheel), the entry needs `VERTEX | FRAGMENT`, not just `VERTEX`. Symptom: `CreateRenderPipeline` fails with "Entry point's stage (Fragment) is not in the binding visibility in the layout (Vertex)", cascading to per-frame `SetPipeline([Invalid RenderPipeline])` + `Submit([Invalid CommandBuffer])` spam (cloning particle-life-gpu, whose fragments never read `view`, hides this until Chrome verify). `swarmalators/index.ts` is the reference for a Particle-Life sibling: free-space (no toroidal wrap), first-order integration, per-particle phase, colour-from-phase in the fragment (no palette buffer), fixed centred view (COM conserved → no auto-fit).
- **Run persistence / resume seam (`resumeConfig` + `armPersistence` + `clearPersistedRun`, #226; `boxcar2d` is the reference):** a diversion that persists a *bred* runtime (not just its config) owns its own `localStorage` (versioned, fail-soft — every read returns null on corrupt/stale/quota, never throws) and exposes three optional `Diversion` hooks the framework routes. **Resume is Play-screen only** (the Config screen mounts a live `AnimationHost` preview — resuming there would desync form ⇄ preview). `PlayScreen` calls `resumeConfig(params, direct)` where `direct = navType==='POP'` (a reload / bookmark / back-forward, NOT an in-app `<Link>` Play click — so a just-configured world is always honored); resume fires only on a **direct seedless** load, and an explicit `?seed=N` is always a fresh reproducible run. Two seams that bit hard and MUST be kept: **(1)** the resume decision can't be re-derived inside `setup()` (it only sees `config`, which can't tell a seedless resume from an explicit `?seed` that happens to match) — it's stashed by `resumeConfig` in a module var that `setup()` reads but **must NOT clear** (React strict-mode double-invokes `setup()` in dev). **(2)** persistence-*arming* is a SEPARATE concern from resume, owned by a `PlayScreen` effect with cleanup (`armPersistence(config)` on mount, `armPersistence(null)` on unmount) — NOT a sticky flag set inside `resumeConfig`, or it leaks across in-app navigations and the Config-preview / Gallery-thumbnail mounts (which never arm) silently clobber the bred run. Belt-and-suspenders: the auto-save is additionally gated on `sameRun(armedConfig, cfg)` so a stale arming can't write a foreign config. Verify the clobber path by clicking the **in-app** `← config` `<Link>` (SPA nav keeps module state alive) — a full-page reload re-inits modules and hides the leak. Determinism keystone: since only `PlayScreen` calls these hooks, the codec / "same seed = same run" tests never resume and never persist.
