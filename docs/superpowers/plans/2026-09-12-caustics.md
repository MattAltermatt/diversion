# Caustics Implementation Plan (#338)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Ship `src/diversions/caustics/` — the bright web of refracted sunlight on a pool floor, straight
down, endless and calm.

**Architecture:** Port the validated mockup behind the `Diversion` contract **first**, as one working piece,
and look at it. Then test the pure halves. `spectrum.ts` builds the wave trains; `phase.ts` turns elapsed

## Global Constraints

- Node 24. `npm test`, `npm run lint` (`--deny-warnings`), `npx tsc -b --noEmit`, `npm run build`,
  `npm run size`, `npm run check:pwa`, `npm run check:preload`, `npm run check:cache` must all pass.
- A diversion folder needs **both** `meta.ts` and `index.ts`, or it silently vanishes from the gallery.
- Tests co-located as `*.test.ts`. `erasableSyntaxOnly` **and** `verbatimModuleSyntax` are on: no `enum`,
  and type-only imports must say `import type`.
- **Accumulation texture is `R16F`, never `R32F`** — float32 is not filterable in core WebGL2, so a `LINEAR`
  sampler over it returns 0 with no GL error and the entire caustic vanishes. This is **not a new finding**:
  `physarum/gl.ts` and `labyrinth/gl.ts` already ship exactly this target
  (`R16F` / `RED` / `HALF_FLOAT` / `LINEAR`), and this plan follows them rather than the mockup.
- **There is no `R8` fallback. `initGL` THROWS when neither float-colour extension is present.** The
  declared fallback was dead on arrival and would have shipped a silently blank pool: `R8` is a *normalized*
  target, so with `blendFunc(ONE, ONE)` and `SPLAT_FS` emitting `1.0` every texel saturates on its **first**
  ray; `RESOLVE_FS` then computes `e = 1/uMean = 1/14 = 0.071` and `x = max(e − 0.88, 0) = 0`, i.e. flat
  water with no caustic anywhere, no GL error, forever. Six diversions already settled this the other way —
  `labyrinth/gl.ts:316`, `physarum`, `foam`, `kuramoto`, `gpu-fluid`, `excitable-media` all throw — and
  `DiversionErrorBoundary` is the affordance. Accept either `EXT_color_buffer_float` or
  `EXT_color_buffer_half_float`; R16F rendering needs one of them and no browser shipping WebGL2 lacks both.
- **⚠️ The framework's `dt` and `t` are MILLISECONDS; the mockup's are SECONDS.** `useAnimationLoop.ts:11`
  — *"onFrame receives elapsed time t (ms) and delta dt (ms)"* — clamped at `Math.min(now - last, 50)`
  (`:28`), which **is** the mockup's own `0.05` s clamp, so do not re-clamp. A literal port of
  `t += dt * tempo * 60` runs the piece **1000× too fast**, destroying the one property the owner's brief is
  entirely about. And it must stay an **integration**: `state.clock += (dt / 1000) * cfg.tempo * 60`, never
  `uTime = t * cfg.tempo * 60`, or every intermediate value of a live Tempo drag teleports the whole surface.
- `teardown(state)` receives **no context** — stash `gl` on state.
- **`makeGLContext()` (`src/test-setup.ts`) has no `checkFramebufferStatus`, no `texStorage2D`, no
  `getError`, and no `createBuffer`/`bufferData`/`vertexAttribPointer`.** Use `texImage2D(…, null)`, keep
  both passes attribute-less via `gl_VertexID` as the mockup is, and call `gl.getError()` nowhere on the
  frame path. `diversionSmoke` mounts this against the mock, so a missing call is a suite failure.
- **Six PostToolUse(Edit|Write) hooks fire on `src` writes, not two.** `typecheck-on-edit` runs a

- [ ] **Step 1: Port the seven modules from the mockup**

Read `docs/mockups/2026-09-12-caustics.html`. **Keep the shaders verbatim except for the changes
below** — an earlier draft said "verbatim" and then silently required three new uniforms, which is exactly
the instruction a literal reader follows wrongly.

**Write in dependency order** — `schema.ts`, `presets.ts`, `spectrum.ts`, `phase.ts`, `gl.ts`, `meta.ts`,
docs, `index.ts` — because `typecheck-on-edit` runs a project-wide `tsc -b` after *every* write and `gl.ts`
imports `CausticsConfig` from `schema.ts`.

**The ten deliberate departures** (the list is exhaustive; the round-4 panel added 1, 7-10 and corrected 5-6):

1. **`uPal` and its three baked branches are gone.** `RESOLVE_FS` takes `uniform vec3 uBackground` and
   `uniform vec3 uLight`. Uploaded as **linear**: `pow(hexToRgb(c), 2.2)` on the CPU, `hexToRgb` from
   `../../framework/color` (returns 0..1 floats). The mockup's constants are pre-gamma and the shader
   gamma-encodes on output, so a raw hex upload renders a different colour than the picker shows.
2. **The hardcoded `w / 0.30` tile pitch** becomes `uniform float uTileSize`.
3. **The jitter is seeded, stratified, and its draw order is PINNED** — Step 2. Every threshold in this plan
   is measured against that exact consumption order; a different one invalidates all of them.
4. **`setSlosh` uses `(i + 1) / NT <= slosh`**, not the mockup's `i / (NT - 1) < slosh`, which leaves the
   shortest train travelling at `slosh = 1`. This form preserves the mockup's behaviour at the
   owner-approved `slosh = 0.70` (7 of 11 standing) and at Breezy's `0.55` (6 of 11). The other obvious fix,
   `i / NT < slosh`, gives 8 and 7 — it changes what the owner approved.
5. **`accSizeFor` gets the cap (`ACC_MAX_PX`), and the grid derivation rounds UP** — Step 3. The old label
   said "`gridFor` gets a cap", which is wrong twice over: the cap is entirely in `accSizeFor`, and a
   literal reader who caps `gridFor` breaks two of its tests. The second half is the undeclared departure
   the panel caught: the mockup uses `Math.round` in the grid derivation, the plan uses `Math.ceil`, and
   that is what makes `gridW*gridH >= accW*accH*R` unconditional — with `round` the mockup actually
   *undershoots* (1058×662 → 9,803,966 rays against 9,805,544 needed).
6. **`SPLAT_VS` interpolates `${REFRACT_K}` rather than hardcoding `0.2481`,** so the shader and the test
   guard cannot drift apart. (It is *already* a template literal in the mockup — `uniform vec4 uTrain[${NT}]`
   — so only the `${REFRACT_K}` interpolation is new. Keep `REFRACT_K` non-integer-valued: a whole number
   would emit a GLSL **int** literal and the shader would stop compiling.)
7. **The clock is milliseconds and is integrated, not multiplied** — see Global Constraints.
   `state.clock += (dt / 1000) * cfg.tempo * 60`, then `writePhase(spec, state.clock)` and
   `uTime = state.clock`.
8. **`floor` is a string enum and `uFloor` is an int.** `FLOOR_INDEX.indexOf(cfg.floor)`. A mapping that
   sends Plain → 0 renders the wrong floor and passes every test in this plan, because `diversionSmoke`
   never inspects uniforms.
9. **There is no `R8` fallback; `initGL` throws instead** — see Global Constraints.
10. **Breezy's `ripple` is `0.0069`, not the mockup's `0.0070`.** 0.0070 is off the declared
    `min 0.0015, step 0.0002` grid ((0.0070−0.0015)/0.0002 = 27.5); 0.0069 lands on 27 exactly. A 1.4%
    change to a preset the owner saw — small, but it belongs in this list rather than in a comment. Every
    other preset value is already on its grid (verified across tempo, gust, slosh, spread, depth, tilt).

- `render` derives extent from `gl.drawingBufferWidth/Height` — **not** `accW/accH`, whose independent

- Cache uniform locations in `initGL` only; `resizeTargets` never touches a program.

- [ ] **Step 2: The spectrum, with the RNG draw order pinned**

```ts
// `spectrum.ts` is the one block shown without its imports in earlier revisions.
// mulberry32 lives in the framework and is NEVER re-implemented per diversion —
// `rng.ts:1-4`: "was duplicated bit-for-bit across five files … Diversions import
// from here; they never own a private copy."
import { mulberry32 } from '../../framework/rng'

const HEADING = 0.62
const GRAVITY = 9.81

export const wavelengthAt = (i: number) => LAM_MAX * Math.pow(LAM_MIN / LAM_MAX, i / (NT - 1))

/** How much of the spectrum stands rather than travels, LONG MODES FIRST -- a
 *  basin's seiches are its long modes, while fine chop stays local and travelling. */
export function setSlosh(spec: Spectrum, slosh: number): void {
  for (let i = 0; i < NT; i++) spec.standing[i] = (i + 1) / NT <= slosh ? 1 : 0
}

export function buildSpectrum({ tilt, spread, slosh, seed }: {
  tilt: number; spread: number; slosh: number; seed: number
}): Spectrum {
  const rnd = mulberry32(seed)
  // PINNED DRAW ORDER, exactly 2*NT-1 draws. Every threshold in this plan is
  // measured against this order; changing it invalidates all of them.
  //   NT   -> one STRATIFIED jitter per equal bin of [-1, 1)
  //   NT-1 -> Fisher-Yates, so bin order does not correlate with wavelength
  //
  // Stratified, not NT independent uniforms: with independent draws the headings
  // occasionally cluster, and a near-collinear spectrum renders the directional
  // lattice this piece was retuned to remove. Measured over 300,000 seeds --
  // independent: 122 seeds past the dispersion bar (about 1 visit in 2,460, and
  // Play rolls a fresh seed every visit), max 0.9911. Stratified: ZERO, max
  // 0.8684, with the typical look unchanged (mean 0.682 -> 0.659).
  const jit = Array.from({ length: NT }, (_, i) => ((i + rnd()) / NT) * 2 - 1)
  for (let i = NT - 1; i > 0; i--) {
    const k = Math.floor(rnd() * (i + 1))
    ;[jit[i], jit[k]] = [jit[k], jit[i]]
  }

  // Amplitude falls with wavelength as lambda^tilt. Focusing power goes as a*k^2,
  // so tilt 2.0 gives every scale equal power (organic, multi-scale); below it the
  // shortest train dominates and every cell comes out the same size -- the
  // chain-link fence the owner rejected; above it the swell leads and the fine
  // detail disappears into cracked glass.
  const amp: number[] = [], wavenum: number[] = []
  let sumSq = 0
  for (let i = 0; i < NT; i++) {
    const lam = wavelengthAt(i)
    const k = (2 * Math.PI) / lam
    wavenum.push(k); amp.push(Math.pow(lam, tilt))
    const c = amp[i] * k * k
    sumSq += c * c
  }
  const rms = Math.sqrt(sumSq / NT) || 1

  const trains = new Float32Array(NT * 4)
  const trainsB = new Float32Array(NT * 4)
  const omega = new Float64Array(NT)
  for (let i = 0; i < NT; i++) {
    const f = i / (NT - 1)
    const k = wavenum[i]
    // Directional spreading: swell holds the wind line, chop fans out around it.
    // Isotropic headings are half of what makes the picture read as a lattice.
    const ang = HEADING + spread * (0.16 + 1.3 * f) * Math.PI * jit[i]
    trains[i * 4 + 0] = Math.cos(ang) * k
    trains[i * 4 + 1] = Math.sin(ang) * k
    trains[i * 4 + 2] = i * 1.7 + jit[i] * 2.4   // spatial phase, reusing the jitter as the mockup does
    trains[i * 4 + 3] = 0
    omega[i] = Math.sqrt(GRAVITY * k)            // deep-water dispersion
    trainsB[i * 4 + 0] = (amp[i] / rms) * CURV_TARGET
    // The gust ruffles SHORT waves and barely touches the swell, so a gust changes
    // the local cell SIZE rather than merely the brightness. Scaling every train
    // equally is the version that leaves the picture stationary.
    trainsB[i * 4 + 1] = Math.pow(f, 1.5)
  }
  const spec: Spectrum = { trains, trainsB, omega, standing: new Uint8Array(NT) }
  setSlosh(spec, slosh)
  return spec
}
```

And `phase.ts` in full:

```ts
import { NT, type Spectrum } from './spectrum'

const TAU = Math.PI * 2

/** Fill each train's per-frame time terms.
 *
 *  travelling:  h = a*sin(k.p + phi - wt)     -> offset = -wt (wrapped), weight = 1
 *  standing:    h = a*sin(k.p + phi)*cos(wt)  -> offset = 0,              weight = cos(wt)
 *
 *  Both collapse to the SAME one-trig form in the shader,
 *  `grad += a*k*cos(k.p + phi + offset) * weight`, because a standing wave's time
 *  factor is uniform over the surface. Standing therefore costs nothing extra --
 *  which is what makes a pool (a closed basin, whose long modes are seiches with
 *  nodes that stay put) as cheap to render as open water.
 *
 *  The offset is wrapped: an unbounded accumulated phase loses float32 precision
 *  over a multi-hour unattended run, and the motion would quantize. */
export function writePhase(spec: Spectrum, t: number): void {
  for (let i = 0; i < NT; i++) {
    const wt = spec.omega[i] * t
    if (spec.standing[i]) {
      spec.trainsB[i * 4 + 2] = 0
      spec.trainsB[i * 4 + 3] = Math.cos(wt % TAU)
    } else {
      spec.trainsB[i * 4 + 2] = -(wt % TAU)
      spec.trainsB[i * 4 + 3] = 1
    }
  }
}
```

- [ ] **Step 3: Cap the ray budget**

The mockup clamps DPR to 1.75; `AnimationHost.tsx:180` clamps to **2** and hands `webgl` device pixels. So
the shipped piece runs ~31% more rays than was measured, and nothing bounds it:

```text
surface                       device px   acc px (0.42^2)    rays (x14)
1440x900 @1.75 (mockup)         3.97 M       0.700 M          9.8 M   <- the "60 fps" measurement
1440x900 @2    (shipped)        5.18 M       0.914 M         12.8 M
4K 3840x2160 @1                 8.29 M       1.463 M         20.5 M
5K 2560x1440 @2                14.75 M       2.601 M         36.4 M
```

```ts
/** Rays scale with accumulation AREA, which scales with device pixels without
 *  bound: a 5K display would ask for 36M single-pixel point primitives per frame.
 *  Cap the buffer and let it soft-scale -- the caustic is a smooth field, so
 *  resolving slightly below the display and upsampling is invisible next to
 *  dropping frames. 720_000 sits a little above the mockup's measured-good
 *  1058x662 (700,396 px), preserving aspect. */
export function accSizeFor(w: number, h: number): { accW: number; accH: number } {
  let accW = Math.max(2, Math.round(w * ACC_SCALE))
  let accH = Math.max(2, Math.round(h * ACC_SCALE))
  const over = (accW * accH) / ACC_MAX_PX
  if (over > 1) {
    const s = Math.sqrt(over)
    accW = Math.max(2, Math.round(accW / s))
    accH = Math.max(2, Math.round(accH / s))
  }
  return { accW, accH }
}

/** gridH >= accH*sqrt(R) and gridW >= gridH*aspect, so gridW*gridH >= accW*accH*R
 *  unconditionally -- no correction loop is reachable. */
export function gridFor(accW: number, accH: number): { gridW: number; gridH: number } {
  const aspect = accW / accH
  const gridH = Math.max(8, Math.ceil(Math.sqrt((accW * accH * RAYS_PER_PX) / aspect)))
  const gridW = Math.max(8, Math.ceil(gridH * aspect))
  return { gridW, gridH }
}
```

/** Fraction of floor receiving >= 1.5x undisturbed light density, i.e. where a
 *  bright filament exists. Intensity is 1/|det J| with J = I - depth*K*H(h), so
 *  det < 0.67 is "half again as bright".
 *
 *  NOT a fold test (det < 0). Measured with an analytic Hessian on every seed
 *  tried, the SHIPPED defaults fold exactly 0% of the time and still render a
 *  bright web -- the caustic here is pure contraction, and a fold-sign guard
 *  rejects the configuration the owner approved.
 *
 *  0.67 and not 0.5, also measured: at 0.5 the defaults floor at 0.00065 over
 *  seeds 1..40 against a 0.01 bar, so which integer is typed as the seed default
 *  would decide whether this suite passes. At 0.67 the same sweep floors at
 *  0.03781 -- a 3.8x margin -- and the vacuity control still reads exactly
 *  0.00000. (0.87 was measured too and is worse: the control starts scoring.)
 *
 *  Analytic Hessian, not a finite difference: a difference step near the 0.09 m
 *  shortest wavelength damps its curvature badly at large `scale`. */
function brightFraction(cfg: ReturnType<typeof causticsSchema.parse>, t: number, n = 192): number {
  const spec = buildSpectrum(cfg)
  writePhase(spec, t)
  const dk = cfg.depth * REFRACT_K
  const ext = cfg.scale
  let hits = 0
  for (let j = 0; j < n; j++) for (let i = 0; i < n; i++) {
    const x = (i / (n - 1) - 0.5) * ext, y = (j / (n - 1) - 0.5) * ext
    // The shader modulates short-wave amplitude by a drifting gust field. Include
    // it, so the guard measures the renderer rather than a model of it. Measured
    // effect at the defaults is 0.6% -- it is here for that reason, not this one.
    const gn = (Math.sin(2.05 * x + 1.25 * y + t * 0.246)
              + Math.sin(-1.55 * x + 2.35 * y + t * 0.198)
              + Math.sin(0.80 * x - 1.90 * y + t * 0.162)) / 3
    let hxx = 0, hxy = 0, hyy = 0
    for (let q = 0; q < NT; q++) {
      const kx = spec.trains[q * 4], ky = spec.trains[q * 4 + 1]
      const m = 1 + cfg.gust * gn * spec.trainsB[q * 4 + 1]
      const a = cfg.ripple * spec.trainsB[q * 4] * spec.trainsB[q * 4 + 3] * m
      const s = Math.sin(kx * x + ky * y + spec.trains[q * 4 + 2] + spec.trainsB[q * 4 + 2])
      hxx -= a * s * kx * kx; hxy -= a * s * kx * ky; hyy -= a * s * ky * ky
    }
    if ((1 - dk * hxx) * (1 - dk * hyy) - dk * dk * hxy * hxy < 0.67) hits++
  }
  return hits / (n * n)
}

/** The WORST instant, not t=0. At t=0 every standing train sits at its coherent
 *  peak and the figure reads 2-9x the typical moment, so a config could pass here
 *  and still be mottle for most of its life. */

  Math.min(...[0, 0.7, 2.0, 3.7, 9.1].map((t) => brightFraction(cfg, t, n)))

### Task 8: Docs, gotchas, then the code panel (inline)

- [ ] **Step 1: CLAUDE.md gotchas** — under "Gotchas learned":
  - A caustic is a **scatter**, not a fullscreen fragment pass: intensity lives on the surface grid and must
    be deposited at the landing point, and the inverse map is three-valued exactly where caustics exist.
  - **Do NOT add "`R32F` is not filterable in core WebGL2"** — `physarum/gl.ts` and `labyrinth/gl.ts` have

    worth writing down: **a normalized `R8` target is not a graceful fallback for an additive splat** — it
    saturates on the first ray and renders a blank field with no GL error, which is the same silent-failure
    shape one tier down.
  - **A bright caustic does not require a fold.** Measured: the shipped default folds 0% of the time and
    still renders a crisp web, by contraction alone. A `det < 0` guard rejects good configurations — and
    `1/|det|` diverges at a fold by construction, so a fold-sign metric has no scale to calibrate against.
  - Equal amplitudes across a wave spectrum make focusing scale as `k²`, so the shortest wave wins
    everywhere and the result reads as a chain-link fence.
  - **Stratify a jitter whose dispersion matters.** Independent draws collapse occasionally — measured 1 seed
    in 2,460 here — and a piece that rolls a fresh seed every visit will show it.
  - A gust field must be authored at **in-frame** wavelength; ~20 m gusts against a 6 m field do nothing.
  - A shader that gamma-encodes on output must be fed **linear** colour; a raw hex upload renders a
    different colour than the picker shows.

## Appendix A — accepted risks

**1. Moiré from a regular ray lattice.** `gridFor` pins rays-per-axis-per-texel at `sqrt(RAYS_PER_PX)` =
3.742 at every resolution (measured 3.7429 at a 319×202 tile, 3.7420 at 1058×662, 3.7423 at 2150×1210 — it
does **not** drift). Each texel therefore catches 3 or 4 rays per axis, 9 to 16 against a mean of 14.
*Cheaper alternative:* a per-vertex hash jitter, trading the beat for white noise. *Rejected for now*
because the mockup runs this identical ratio, so the lattice is what the owner approved — **with one caveat
this entry keeps**: `ACC_MAX_PX` is new, and on a 5K display it raises the accumulation→device upsample from
the mockup's 2.38× to ~4.5×, so the same beat is drawn at up to 1.9× the angular size the owner saw.
The round-4 naysayer argued the jitter should ship unconditionally as "strictly cannot make a 3.742:1 lattice
worse". **Rejected, and the reason sharpens the entry:** at 14 rays/px, jittering the sample lattice does not
remove variance, it *spends the same budget on* variance — and the mockup's own note records that below ~14
rays/px "the floor sparkles black", i.e. shot noise is the failure mode this ray count is sized against. So
the trade is a lattice beat against sparkle, not against nothing.

⚠️ **CORRECTED 2026-09-14 — the rest of this entry rested on a unit error, and the error was load-bearing.**
It read: *"It is also not a defect on the owner's own display: at 1440×900 `accSizeFor` returns {605, 378},
uncapped, so the shipped configuration there is byte-identical to the approved one. The risk lives only above
the cap — which is why the verify looks at 3840×2160, where it binds."* That computes `accSizeFor` in **CSS**
pixels. `AnimationHost` hands a `webgl` diversion **device** pixels, so the real call on that display is
`accSizeFor(2880, 1800)` = {1073, 671} — **capped**. The cap binds above 4.08 M device px, i.e. on every DPR-2
display, including the machine the look was approved on. The wrong number was then used both to reject the
per-vertex jitter mitigation and to scope the verify to 3840×2160 only.

What survives re-measurement: the mockup clamped DPR to 1.75, so on a DPR-2 display its own canvas was
sub-native and composited up again — an effective ~2.72× against the shipped 2.68× at the same window, i.e.
the ship is marginally **sharper** there, not softer. What is genuinely undefended is that the mockup's blur
was scale-invariant while the shipped one grows with window area: 3.27× at the size the shipped capture was
taken, 4.53× at 5K. Tracked in **#390**. Note also that `RESOLVE_FS`'s 5-tap kernel is authored in
`uAccTexel` units, which is the mechanism by which that widening becomes visible as **softer filaments**
rather than only as moiré.
Record both.

**2. `CURV_TARGET = 120` is a unit choice, not physics.** The shader only uses `ripple × trainsB[i]`, so it
is a free scale factor. *Cheaper alternative:* set it to 1 and rescale `ripple`. *Rejected* because
`ripple`'s defaults and bounds are owner-tuned values he has seen; renaming the units under them changes
every number he approved for no behavioural gain.

**3. Wavelengths are absolute while `scale` is a 3–14 m slider.** `LAM_MAX = 1.15 m` is 38% of the view at
scale 3 and 8% at 14. *Cheaper alternative:* make them a fraction of `scale`. *Rejected* because wavelength
is a physical property of water — a pool's waves do not get longer because you stepped back. **The sharper
end is `LAM_MIN`:** on a gallery tile (~319 accumulation texels across 9.6 m) the 0.09 m train gets ~3
texels, and ~1 on a 280 px DPR-1 tile — below Nyquist, so a tile renders a genuinely coarser spectrum than
Play does, not merely a smaller one. Accepted rather than fixed: a tile is a thumbnail advertising the
piece, and scaling `LAM_MIN` with the buffer would make the piece change character with its container,
which is the defect #319 was fixed to remove. Task 1b records what a tile actually looks like.

**The round-4 panel named a third option the entry never considered, and it is the right one if the tile
reads badly:** *band-limit* the spectrum — drop trains whose wavelength falls below ~4 accumulation texels
and renormalise `rms` over the survivors. That is a level-of-detail decision, not a rescale: it removes what
cannot be shown rather than changing what is shown, and Play stays byte-identical. It is one loop bound in
`buildSpectrum` plus passing `accW / scale` in. **Deferred rather than adopted**, because it still makes the
piece render differently in different containers — the thing #319 exists to prevent — so it needs the
evidence from the tile reading before it is worth that cost. Two numbers the entry also got wrong and the
verify must collect: the finest features sit at ~λ/2, i.e. **~1.5 texels**, not 3, before the 5-tap blur;
and the spec's "a tile is ~484k rays" is a DPR-1 figure — at the host's clamped DPR 2 a ~380 px tile is
**~902k rays**. Cheap either way (`gpuBudget.MAX_LIVE_GPU = 6`), but **read the gallery's own fps**, which
neither verify step currently does.

## Appendix B — what the panel changed

Three rounds, two reviewers and a naysayer each. The design did not move; these are the substantive
corrections, kept because each names a trap the next reader could fall into.

1. **The spec's physical model was wrong.** It claimed the web requires the surface to fold. The shipped
   default folds 0% of the time and renders a bright web by contraction. Both the draft's `det < 0` guard
   and its `det < 0.5` successor failed at the owner's own defaults; `det < 0.67` is the third attempt and
   the first that two independent implementations agree is robust across seeds.
2. **The renderer is a scatter**, not the fullscreen fragment pass #338 specified — which resized the piece
   from S–M to M.
3. **`setSlosh` had an off-by-one** inherited from the mockup: at `slosh = 1` the shortest train never
   stood. Two candidate fixes differed at the owner-approved 0.70; the one preserving 7-of-11 was taken.
4. **The palette needed an sRGB→linear conversion**, and it was applied to the backgrounds one revision
   before the lights. No test catches a wrong light — a lighter one only raises the contrast ratio.
5. **The ray budget was uncapped**; a 5K display would have asked for 36M rays per frame.
6. **The jitter is stratified** because independent draws collapsed the headings on ~1 seed in 2,460, and
   Play rolls a fresh seed every visit.
7. **The RNG draw order is pinned** because every measured threshold here depends on it.
8. **Several tests were vacuous** — one grepped GLSL for a JavaScript constant; one perturbed each config
   field to its own current value; two were algebraic identities. Each is replaced by something that fails
   under mutation, and each mutation is specified.

### Round 4 (2026-09-14) — two reviewers and a naysayer, against the consolidated document

The design still did not move. What changed:

9. **The clock was wrong by 1000×**, and by shape. The framework's `dt`/`t` are milliseconds
   (`useAnimationLoop.ts:11`); the mockup's are seconds. A literal port destroys the one property the brief
   is about. It must also be an *integration* (`clock += …`), or a live Tempo drag teleports the surface.
   Nothing in the suite reached it — the phase tests drive `writePhase` with literals and never call `frame`.
10. **The `R8` fallback rendered a blank pool**, and a test entrenched it. Replaced with a throw, matching
    the six diversions that already do this.
11. **The renderer is NOT a novel class.** `physarum` and `labyrinth` already ship additive unit-point splat
    into `R16F`. The spec's claim to the contrary is the stated basis of the S–M → M resize, so that sizing
    now rests on nothing — and the plan ports from the HTML file when the repo has a proven template.
12. **The `seed` default was unwritten** while the plan's own comment called it decisive, and the brightness
    guard tested one seed although `urlCodec` rolls one of 10⁹ per visit. Pinned to `1`; the guard sweeps.
13. **Nothing pinned the "pinned" draw order.** A golden vector now does, in three lines. Worth recording
    that the naysayer inferred from its absence that the measurements never happened — and was **wrong**:
    both reviewers independently re-implemented the plan's code and reproduced every figure, one of them
    re-running the 300,000-seed sweep to the plan's exact `0.86840 at seed 6607`. The absent artifact was
    real evidence of a real gap; the inference drawn from it was not.
14. **`slosh` could ship inert with a green suite** — `setSlosh` mutates in place, so neither the
    live-apply nor the rebuild test could see it. For the piece's headline mechanism.
15. **Four smaller undeclared departures** (the `floor` enum→int mapping, `ceil` vs `round` in the grid
    derivation, Breezy's `0.0070` → `0.0069`, the `accSizeFor`/`gridFor` mislabel) — in a list the document
    itself bills as exhaustive, having already been bitten once by exactly that.
16. **`expect(caustics.resize).toBeDefined()`** passes against an empty body, which has the identical stated
    consequence. Driven now.
17. **Eight of thirteen fields had no `help`**, which canon makes a MUST and no sweep enforces.
