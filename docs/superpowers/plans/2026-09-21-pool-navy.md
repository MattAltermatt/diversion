```ts
/** What every later module mutates. Carries BOTH faction forms on purpose:
 *  a string for the ported captain's equality checks, an index for the
 *  escalation schedule and the palette. */
export interface Ship {
  readonly id: string
  readonly faction: string
  readonly factionIndex: number
  spec: ShipSpec
  weapon: WeaponSpec
  hp: number
  alive: boolean
  hull: HullState
  turretBearing: number
  reload: number
  captain: CaptainState | null
  prevHeadingError: number | undefined
  /** Seconds below the way threshold. A pinned hull cannot steer. */
  stalledFor: number
  /** Wake samples, in metres. Produced by sim.ts, consumed by render.ts. */
  trail: Array<{ x: number; y: number }>
}

/**
 * Speed a hull may still make, as a fraction of its own top speed.
 *
 * `floor + (1 - floor) * h^p`, with p SOLVED so the curve passes exactly
 * through (LIMP_HP, limpSpeed). A straight line cannot do this: it is pinned at
 * both ends, so dragging 20% condition down to a limp drags the zero-condition
 * floor with it, into the speed below which the rudder stops biting.
 */
export function limpExponent(limpSpeed: number): number {
  const reach = (limpSpeed - SPEED_FLOOR) / (1 - SPEED_FLOOR)
  if (reach <= 1e-6) return 12
  return Math.log(reach) / Math.log(LIMP_HP)
}

export function speedScale(hpFraction: number, limpSpeed: number): number {
  const h = Math.max(0, Math.min(1, hpFraction))
  return SPEED_FLOOR + (1 - SPEED_FLOOR) * Math.pow(h, limpExponent(limpSpeed))
}

/**
 * Throttle that settles a hull at `target` of its top speed. Drag carries a
 * linear AND a quadratic term, so scaling throttle directly would produce a
 * slow-down curve nobody chose. Inverting the drag law makes the knob mean
 * what it says: T(s·vt)/T(vt) = (s² + f·s)/(1 + f).
 */
export function throttleForSpeedFraction(target: number): number {
  const f = LINEAR_DRAG_FRACTION
  const s = Math.max(0, Math.min(1, target))
  return (s * s + f * s) / (1 + f)
}
```

## Accepted risks

**1. Four weapons slow the piece 29 % below the tuned pace.**
*The objection:* the pace was tuned cannon-only at 6.20 sunk/min; the measured mixed-weapon rate is
**4.20**, a new faction every ~43 s rather than ~29 s.
*The cheaper alternative:* drop `hullHp` from 90 to ~65 to restore the tuned pace.
*Why rejected for now:* `hullHp` is a tuning literal and the owner set it deliberately this session
("their hulls are more powerful"). Changing it is an owner call, not an agent's. **Surfaced in the
handoff as a decision, with the numbers.**

**2. The co-rotate/counter-orbit duel split is a hypothesis, not a finding.**
*The objection:* the spec's §7.1 story about 45 °/s straddling the 32/64 °/s requirements is
unverified, and a similar claim was already wrong once this session.
*The cheaper alternative:* delete the story and justify 45 °/s purely on the measured 23 % pace cost.
*Why accepted:* the number is justified by the measurement either way, so the piece is correct
whichever the story turns out to be. Task 12's measurement step should settle it; **if it comes back
unimodal, delete spec §7.1 rather than retro-fitting.**

**3. `palette.ts` and `render.ts` thresholds have no probe behind them.**
*The objection:* the spec's own rule is that authored thresholds guard nothing.
*The cheaper alternative:* extend the probe to cover both before writing the tasks.
*Why accepted:* both are measurable off the working module in the same task that creates it, which
is the rule the spec actually states; Task 7 Step 3 and Task 10 make that measurement mandatory, and
Task 7 carries a deliberately-planted placeholder assertion that must be replaced.
